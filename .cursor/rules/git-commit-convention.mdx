# Git Commit Convention

## 📝 커밋 메시지 형식

```
<type>: <description>

[optional body]

[optional footer]
```

## 🏷️ Type 종류

- **feat**: 새로운 기능 추가
- **update**: 기존 기능 업데이트/개선
- **fix**: 버그 수정
- **style**: 코드 스타일 변경 (포맷팅, 세미콜론 등)
- **refactor**: 코드 리팩토링 (기능 변경 없음)
- **docs**: 문서 변경
- **test**: 테스트 코드 추가/수정
- **chore**: 빌드 프로세스, 패키지 매니저 설정 등
- **perf**: 성능 개선
- **ci**: CI/CD 설정 변경

## ✅ 커밋 메시지 작성 규칙

1. **한국어로 작성**
2. **제목은 50자 이내**
3. **제목 끝에 마침표 금지**
4. **제목은 명령형으로 작성**
5. **본문은 "무엇을" 보다 "왜"에 집중**

## 📋 예시

```bash
feat: 댓글 좋아요/싫어요 기능 추가

사용자가 댓글에 반응할 수 있도록 좋아요/싫어요 버튼을 구현했습니다.
- CommentLike 모델 추가
- 좋아요/싫어요 API 엔드포인트 구현
- 실시간 카운트 업데이트

Closes #123
```

```bash
fix: 댓글 작성 시 세션 오류 수정

- 로그인하지 않은 사용자가 댓글 작성을 시도할 때 발생하는 오류를 수정했습니다.
```

```bash
style: 댓글 UI 반응형 디자인 개선

- 모바일에서 댓글 섹션의 가독성을 향상시켰습니다.
```

```bash
update: 댓글 삭제 기능 권한 검증 강화

- 본인이 작성한 댓글만 삭제할 수 있도록 권한 검증 로직을 개선했습니다.
```

```bash
chore: prisma 스키마 마이그레이션 추가

- CommentLike 테이블 생성을 위한 마이그레이션 파일 추가
```

```bash
docs: API 문서 업데이트

- 댓글 관련 새로운 엔드포인트들에 대한 Swagger 문서 추가
```
